# Telegram Stars через STEAM.RU и FunPayCardinal: начни здесь

Сборка **0.9.2 Beta** подготовлена для FunPayCardinal **0.1.17.15 из твоего ZIP**. Плагин предназначен для готовых пакетов **50, 100 и 150 звёзд**, максимум 150 суммарно на заказ. По умолчанию покупки запрещены, реальные заказы не захватываются и сообщения покупателям не отправляются.

Проверены исходники и сценарии с подставными ответами. Совместимость интерфейсов проверена по файлам Cardinal; настоящая выдача этой сборкой на твоём аккаунте ещё не подтверждена. При подготовке реальные покупки не совершались. Состояние лота FunPay не проверялось: **оставь его выключенным вручную до испытаний**.

Ты уже работаешь в Codex: здесь можно разбирать архив, исправлять код и запускать безопасные тесты. Ещё один перенос разговора не требуется.

## 1. Что находится в сборке

| Файл | Назначение |
|---|---|
| `plugins/steamru_stars.py` | Обработчики Cardinal и команды Telegram |
| `plugins/steamru_stars_engine.py` | API, расчёты, журнал заказов SQLite |
| `config.example.json` | Пример настроек без секретов |
| `check_api.py` | Необязательная проверка API только чтением |
| `tests/` | Проверки без ключей, сети и покупок |
| `Run_Tests.bat` / `run_tests.py` | Безопасный запуск этих проверок |
| `COMPATIBILITY.md` | Сопоставление с исходниками Cardinal |

Доступны два архива: `FunPayCardinal_Stars_0.9.2_safe.zip` — полный Cardinal с уже размещёнными плагином и безопасным конфигом; `STEAMRU_Stars_0.9.2_safe_plugin.zip` — только расширение для установленного Cardinal. Если скачал полный архив, распакуй его, используй раздел 3 для первого запуска и пропусти копирование файлов в разделе 4.

## 2. Сначала тесты без ключей

На Windows дважды нажми **`Run_Tests.bat`**. Либо открой PowerShell в папке этой сборки:

```powershell
python run_tests.py
```

Этот запуск не обращается к сети и не использует настоящие ключи или боевые настройки. Тестам не нужны golden_key, Telegram token, API key или secret. Они используют вымышленные заказы и ответы API. Результат `PASS` подтверждает эти проверки, а не настоящую покупку или состояние лота. Подробности сохраняются в `TEST_REPORT.txt` и `TEST_REPORT.json` рядом с инструкцией.

## 3. Установи и подключи Cardinal на Windows

В исходном README предлагается Python 3.11. Исправленный запуск дополнительно проверен на Python 3.14.2 до запроса golden_key без подключения аккаунтов. Если Python уже установлен, используй его; иначе установи Python 3.11 или новее с галочкой `Add python.exe to PATH`. Полностью распакуй Cardinal через «Извлечь всё».

1. Запусти `Setup.bat`: исправленный установщик создаёт отдельную папку `.venv`, устанавливает зависимости из `requirements.txt` и проверяет их. Дождись сообщения «УСТАНОВКА УСПЕШНА».
2. Запусти `Start.bat`: появится первоначальный мастер.
3. Введи **локально на своём компьютере** cookie `golden_key` своего аккаунта FunPay. Его можно посмотреть в инструментах разработчика собственного браузера: хранилище cookies сайта `funpay.com`. Мастер ожидает 32 символа. Это отдельный секрет FunPay, не STEAM.RU API key. Не отправляй его в чат или на скриншоте.
4. На вопрос о User-Agent можно нажать Enter: мастер сохранит встроенное значение. Ненужные прокси также пропусти нажатием Enter.
5. Создай личного управляющего Telegram-бота через BotFather. В этой версии Cardinal его username должен начинаться с `funpay`. Введи token локально и придумай пароль длиной хотя бы 8 символов с буквами в обоих регистрах и цифрой.
6. Мастер сохранит `configs/_main.cfg` и завершится. **Запусти `Start.bat` второй раз**.
7. Напиши своему управляющему боту, авторизуйся паролем и открой `/menu`.

Оставь выключенным `autoRestore`/автовосстановление. Для этих лотов также выключи штатную автовыдачу Cardinal: у расширения свой обработчик. Переключатель `autoDelivery` Cardinal сам по себе не запрещает покупки расширения.

Архив закрепляет `requests==2.28.1` и `requests_toolbelt==0.10.1`. Устанавливай зависимости целиком, не обновляй отдельно requests. Для этой пары не подходит urllib3 2.x; корректная установка requests 2.28.1 подбирает urllib3 ниже 1.27. Если старое окружение конфликтует, используй отдельное окружение Python с зависимостями архива. Проверка:

```powershell
python -m pip check
```

## 4. Установи расширение

1. Останови Cardinal.
2. Скопируй **оба** файла `steamru_stars.py` и `steamru_stars_engine.py` из нашей `plugins` в корневую папку `plugins` установленного Cardinal. Не создавай внутри неё вторую папку `plugins`.
3. Запусти Cardinal. Появятся `storage/plugins/steamru_stars_config.json` и `storage/plugins/steamru_stars.sqlite3`.
4. Оставь `mode: "dry_run"`, `capture_paid_orders_in_dry_run: false` и `capture_initial_paid_orders: false`.
5. Проверь журнал: основной плагин загружен без ошибки. Engine — вспомогательный модуль с меткой `noplug`, отдельно в списке плагинов он появляться не должен.

Cardinal умеет загрузку через `/menu` → «Плагины» → «Добавить плагин» с последующим `/restart`. Здесь ручное копирование удобнее: нужны два файла. Секреты и SQLite в Telegram не загружай.

При обновлении сохрани резервную копию SQLite при остановленном Cardinal. **Не удаляй базу ради повторного выполнения заказа**: она защищает от дублей. Настройки старой сборки 250/500/1000 звёзд нужно заменить: новый максимум — 150. Режим захвата заказа сохраняется в базе: тестовая очередь dry_run не превращается в настоящие покупки после переключения LIVE. Неподтверждённые записи старой базы также не закупаются автоматически.

## 5. Привяжи лоты к количеству

В `storage/plugins/steamru_stars_config.json` настрой `lots`. Это **точный заголовок оплаченного лота → звёзд в одной купленной единице**. Ниже фрагмент уже созданного JSON-файла; остальные поля остаются на месте:

```json
"lots": {
  "STEAMRU TG STARS 50": 50,
  "STEAMRU TG STARS 100": 100,
  "STEAMRU TG STARS 150": 150
},
"max_total_stars": 150,
"allowed_subcategory_ids": []
```

Плагин читает полный заказ FunPay и заголовок из поля `summary`, а не произвольный текст покупателя. Суммарное количество = `звёзд в единице × купленных единиц`: 50 × 3 = 150 допустимо, 100 × 2 = 200 запрещено. Нижняя граница — 50, верхняя — 150 даже при попытке увеличить конфигурационный лимит.

`allowed_subcategory_ids` изначально пуст: **обработка запрещена до выбора правильной подкатегории Telegram Stars**. Здесь нужны числовые IDs подкатегорий FunPay. Это не товар `product_id: 55` поставщика и не ID лота. Сверь именно свою подкатегорию; произвольный номер не подставляй.

`lot_ids_to_disable` — отдельная настройка: IDs твоих собственных лотов для аварийного отключения. Перед LIVE требуется `auto_disable_lots_on_pause: true`. ID берётся из формы редактирования собственного лота. Проверь отключение на выключенном тестовом лоте. Плагин не включает лоты обратно.

При нормальной продаже покупатель отправляет получателя в строгом формате:

```text
@telegramuser #ABCD1234
```

Номер должен принадлежать именно его оплаченному заказу; сообщение принимается от того же покупателя в том же чате. Строка без подходящего оплаченного заказа не запускает покупку.

## 6. Необязательная проверка STEAM.RU без покупки

По прежнему обсуждению подтверждены пара `api_key + api_secret`, HMAC-SHA256, сервис `telegram-stars`, товар `55` и успешный `GET /account`. Это прежние сведения, а не новое подключение этой сборки к твоему аккаунту.

Сам **`openapi.json` среди доступных файлов не найден**. На полученном скриншоте документации сверена каноническая строка HMAC: метод, путь с query, timestamp, nonce и SHA256 тела через переводы строк. Это подтверждает правило подписи; полный контракт каталога, статусов и ошибок всё ещё требует сверки с файлом API или безопасным чтением API. Успешный `/account` не проверяет все остальные методы.

Кошелёк ты пока не пополнял. **Вносить деньги сейчас не требуется**: сначала проверь чтение API и актуальную цену товара 55.

Из папки сборки:

```powershell
python check_api.py
```

Ключ и секрет вводятся **скрыто и только локально**, не сохраняются. Скрипт читает `GET /account` и каталог Telegram Stars; не отправляет `POST /orders`. Сверь наличие товара 55, цену USD, min/max и дополнительные поля. При ошибке оставь dry_run и выключенный лот. Предварительная потребность кошелька для будущего теста: `50 × актуальная цена одной звезды USD + min_balance_reserve_usd`. Отдельно учитывается минимальная сумма пополнения у поставщика; её надо узнать в кабинете, здесь она не подтверждена. Это расчёт подготовки, а не инструкция пополнить сейчас.

Переменные окружения процесса Cardinal:

| Переменная | Значение |
|---|---|
| `STEAMRU_API_KEY` | Ключ STEAM.RU |
| `STEAMRU_API_SECRET` | Секрет HMAC из той же пары |
| `STEAMRU_OWNER_TG_ID` | Цифровой ID твоего личного Telegram-аккаунта |
| `STEAMRU_LIVE_CONFIRM` | Дополнительное разрешение покупки; пока не задавай |

Цифровой ID владельца сверяется с авторизованным пользователем в личной панели Cardinal или локальном `storage/cache/tg_authorized_users.json`. Это не ID бота и не username.

Пример скрытого ввода в PowerShell:

```powershell
$steamruKeyInput = Read-Host 'STEAM.RU api_key' -AsSecureString
$steamruSecretInput = Read-Host 'STEAM.RU api_secret' -AsSecureString
$env:STEAMRU_API_KEY = [System.Net.NetworkCredential]::new('', $steamruKeyInput).Password
$env:STEAMRU_API_SECRET = [System.Net.NetworkCredential]::new('', $steamruSecretInput).Password
$env:STEAMRU_OWNER_TG_ID = 'ТВОЙ_ЦИФРОВОЙ_ID'
python main.py
```

Последняя команда выполняется из папки **Cardinal**. Не выводи переменные на экран. Они действуют в текущем окне PowerShell; запуск двойным щелчком из другого окна может не получить секреты.

В управляющем боте `/sr_probe` также читает баланс и каталог без покупки. Команды доступны заданному владельцу в личном чате, когда он уже авторизован паролем в Cardinal.

## 7. Проверь прибыль по фактическому курсу

```text
Эффективный RUB/USD = фактически оплаченные рубли / фактически зачисленные USD
```

Используй зачисление после комиссий. Например, **если** оплачено 106.14 ₽ и зачислено 1.20 USD, курс — 88.45 ₽/USD. Это арифметический пример, не действующий курс твоего кошелька.

После будущего согласованного пополнения внеси в `wallet_paid_rub` фактически оплаченные рубли, а в `wallet_credited_usd` — фактически зачисленные доллары. **Плагин сам вычислит `rub_per_usd` как их отношение**; вручную этот курс задавать не нужно. В `rub_per_usd_updated_at` укажи фактическое время проверки ISO, например `ГГГГ-ММ-ДДTЧЧ:ММ:СС+03:00`. Пока пополнения нет, оставь оба значения `null`: LIVE заблокирован. Не копируй старую дату. По умолчанию через 24 часа курс устаревает и блокирует новые покупки.

```text
Выручка после вывода = сумма заказа FunPay × (1 − комиссия вывода / 100)
Расход = цена одной звезды USD × количество × эффективный RUB/USD + прочие расходы RUB
Прибыль = выручка после вывода − расход
Маржа % = прибыль / сумма заказа FunPay × 100
```

Комиссия 3% в примере — **настройка**, не проверенный тариф твоего аккаунта. Выставь фактическую комиссию и расходы. Плагин проверяет `min_profit_rub`, `min_margin_pct`, остаток и лимиты. Сумма берётся из `.sum` полного заказа; принимается RUB. Автоизменения цен лотов и пополнения кошелька нет.

Цена 68 ₽ за 50 звёзд допустима только если свежий расчёт проходит пороги; прежнее обсуждение цены не доказывает прибыльность.

## 8. Команды и дальнейшая подготовка LIVE

| Команда | Действие |
|---|---|
| `/sr_status` | Режим, разрешение LIVE, пауза, состояния заказов |
| `/sr_probe` | Чтение баланса и каталога, без покупки |
| `/sr_orders` | Последние локальные заказы |
| `/sr_check НОМЕР` | Чтение статуса по сохранённому UUID; без повторной покупки |
| `/sr_pause` | Остановка новых покупок; начатые продолжают проверяться |
| `/sr_resume` | Снятие паузы только при выполненных предохранителях LIVE |

По умолчанию стоит пауза. `/sr_resume` не включает лоты FunPay. После паузы вручную проверяй их состояние: сетевой запрос отключения может не пройти.

Для LIVE одновременно нужны `mode: "live"`, локальные key/secret, цифровой ID владельца, `STEAMRU_LIVE_CONFIRM=I_ACCEPT_REAL_PURCHASES`, свежий эффективный курс, разрешённые подкатегории, правильные лоты/лимиты и аварийное отключение. После изменения конфигурации нужен перезапуск, затем `/sr_resume`.

**Сейчас не включай LIVE.** Сначала тесты, чтение API и проверка привязки. Затем — отдельно согласованная контролируемая первая покупка и подтверждение фактической доставки. Только после неё можно разрешать публичные продажи. Подготовка этой сборки не означает разрешение настоящей покупки.

## 9. Зависшие операции и возвраты

| Случай | Значение и действие |
|---|---|
| Повторное событие/перезапуск | Номер FunPay, SQLite и `external_order_id=funpay-НОМЕР` защищают от повторной отправки. Сохраняй базу. |
| FunPay CLOSED/REFUNDED/PARTIALLY_REFUNDED/UNPAID | Новая покупка запрещена. CLOSED FunPay означает закрытие сделки, не возврат. |
| Встроенный тест ADTEST | Покупка запрещена: заказ вымышленный, несмотря на PAID. |
| Таймаут после POST, обрыв, ответ без UUID | Покупка могла состояться. Новые покупки останавливаются. Найди исходный заказ у поставщика по external_order_id; не отправляй второй. |
| Поставщик review/error/closed/refund | Возврат денег не подтверждён. Требуется сверка исходной покупки; повтор запрещён. |
| Поставщик refunded | Только этот статус подтверждает возврат **у поставщика**. Это не возврат покупателю FunPay. |
| Поставщик completed | Подтверждённое выполнение. Ошибка сообщения покупателю не вызывает новую покупку. |
| FunPay вернул деньги во время обработки у поставщика | Требуется разбирательство: операции на двух площадках не являются одной транзакцией. |

**Автоматических возвратов FunPay нет.** Решение принимает продавец после сверки. Ошибка, отзыв, closed и неоднозначный POST не доказывают возврат поставщика.

Обычную выдачу можно автоматизировать. Полностью автоматическое разрешение неопределённого платежа или спорного статуса гарантировать нельзя: плагин сохраняет операцию, останавливается и требует проверки владельцем/поддержкой.

По умолчанию `capture_initial_paid_orders: false`: заказы, найденные при первом запросе после запуска Cardinal, не импортируются как новые. Записанные операции восстанавливаются из SQLite; незаписанные заказы за время простоя сверяй вручную.

Для автоматического подхвата заказов после простоя можно позже поставить `capture_initial_paid_orders: true`. **Сначала сверяй все старые PAID**: какие ещё не исполнены, какие выполнены вручную, какие записаны в базе. Включение разрешает захватывать подходящие оплаченные заказы, найденные при запуске; ограничения только по возрасту заказа нет. Поле PAID само по себе не доказывает, что продавец никогда не выдавал товар вручную. До такой сверки оставь false.

Один экземпляр плагина на одной базе. Резервные копии с данными покупателей храни локально.

Подробности проверки интерфейсов — в `COMPATIBILITY.md`.

После /sr_resume старые uncertain и needs_review не покупаются повторно; разрешаются только другие готовые live-заказы. Возобновление не означает, что неизвестное списание уже выяснено. Сутки лимита бюджета считаются по UTC и дате начала отправки, поэтому после смены суток прежняя неопределённая операция всё ещё требует отдельной сверки.

Формат Telegram-получателя соответствует показанной документации STEAM.RU: 4–32 латинских букв, цифр или подчёркиваний. Перед покупкой API дополнительно проверяет существование username. Предварительная цена проверяется до POST; если поставщик списал больше, фиксируется фактическая сумма и новые покупки останавливаются. Возможность ограничить само серверное списание максимальной ценой ещё не подтверждена схемой API.

Исправленный Start.bat запускает Python из .venv в том же окне и оставляет ошибку на экране. Setup.bat, Start.bat и check_install.py должны находиться рядом с main.py. Исходный launcher `start python main.py` заменён, чтобы окно с ошибкой не закрывалось сразу.
