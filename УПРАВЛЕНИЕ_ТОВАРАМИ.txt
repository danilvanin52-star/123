STEAM.RU × FunPayCardinal 0.11.0-beta — управление товарами

Открой Start_STEAMRU_LIVE.bat. Введи данные только в его окне. Дождись проверки API, затем отправь /sr_resume ОДИН раз. Проверка большого числа лотов занимает несколько минут. /sr_status показывает прогресс. Дождись «Продажи запущены».

Главная команда — /sr_products. Открой товар кнопкой:
• «Цена»: отправь новую цену в рублях и срок в часах, например 82.50 5.
• «Автоцена»: сразу вернуть расчёт бота.
• «Выключить»: снять товар с продажи; оплаченные заказы продолжают обрабатываться.
• «Включить»: разрешить продажу; бот проверит наличие, баланс и бюджет.
• «Описание»: отправь новый русский текст одним сообщением.
• «Текст бота»: вернуть стандартное описание.
• Для игр «Закрепить» исключает товар из ротации; «Ротация» возвращает его.
После ручной цены автоматический пересчёт ждёт окончания срока. Цена может быть ниже себестоимости — её выбираешь ты. Настройки сохраняются при перезапуске. Для Steam RUB цена указана за 1 ₽ баланса, для остальных товаров — за пакет/код/ключ.

Команды для прямого управления:
/sr_product ID — карточка товара
/sr_price ID ЦЕНА ЧАСЫ — ручная цена (если срок не указан, 5 часов)
/sr_auto ID — вернуть автоцену
/sr_off ID — снять с продажи
/sr_on ID — разрешить продажу
/sr_text ID НОВЫЙ ТЕКСТ — описание
/sr_text_auto ID — вернуть описание бота
/sr_pin ID — закрепить игру
/sr_unpin ID — вернуть игру в ротацию
/sr_rotation off — выключить ротацию (после окончания текущей замены)
/sr_rotation on — включить ротацию
/sr_sync — обновить каталог и автоматические цены; ручные цены сохраняются
/sr_limits USD_НА_ЗАКАЗ USD_В_СУТКИ — изменить бюджеты
/sr_help — эта памятка в Telegram

Пример с первым новым лотом PUBG 60 UC:
/sr_price 79440031 82.50 5
Это цена 82,50 ₽ на 5 часов; после срока вернётся автоцена.

Новые товары:
PUBG Mobile Global: 60 и 325 UC — по ID игрока.
Mobile Legends Global: 42, 78+8, 156+16, 234+23 алмаза — ID игрока и ID сервера, например 123456789 1234.
Free Fire СНГ: 110, 341, 572 алмаза — по ID игрока.
Roblox Россия: коды 50, 100, 199, 255 Robux — выдача кода автоматически в чат.
Apple ID Турция: коды 50, 100, 200 TRY; Apple ID Россия: 500 RUB — выдача кода в чат.
Пароли и коды входа покупателя не требуются. При нескольких ожидающих пополнениях добавляй #номер заказа после ID.

При включении новые товары сверяются через API STEAM.RU. Недоступный сервис или изменившаяся схема остаётся выключенной.
Карта Apple ID Россия 500 RUB при проверке стоила $7,1469. При балансе $5,195 и лимите $6 она не включится. Для этой карты нужны деньги на закупку с резервом и достаточный лимит заказа. Например /sr_limits 8 30 меняет только лимиты; баланс не пополняет.

Ротация ключей: до 3 игр из 20 каждые 5 часов; закреплённые, вручную выключенные и временно оценённые игры пропускаются. Лоты с незавершёнными заказами защищены. Уже оплаченный заказ остаётся привязан к исходному товару.
Неопределённый POST поставщика не повторяется. error/review/closed не означают возврат; только refunded. Проверки выполнялись без реальных закупок новых товаров.


Исправление обработки заказов 13.10.2026
FunPay возвращает покупательские подписи полей: Steam RUB «RUB🔥»/«По логину🔥», у ключей — «СНГ»/«Россия»/«Европа». Эти значения теперь приводятся к проверенным кодам только в нужной категории и типе поля. Валюта USD и другой способ выдачи не допускаются. Проверены поля всех 41 текущих лотов без закупок.
Steam RUB: любая целая сумма 100–500 ₽, включая 156 и 492 ₽. Логин из полного оплаченного заказа используется автоматически; повторно отправлять его в чат не требуется. При отсутствии логина бот попросит его. Изменение принятого логина блокирует покупку.
Повтор чтения до закупки: три отложенные попытки через 30, 90 и 300 секунд. Перед каждой заново проверяются оплата, продавец, покупатель, товар, сумма и бюджеты. При неизвестном результате POST повторной закупки нет; при известном UUID продолжается GET статуса. error/review/closed не означают возврат.
После выполненной выдачи покупатель получает результат, инструкцию активации для кода, просьбу подтвердить заказ и оставить отзыв. Штатный Cardinal благодарит после подтверждения и отвечает на отзывы 1–5 звёзд.
Уведомления о новых заказах и результатах поступают напрямую авторизованному владельцу в личный Telegram. При временной ошибке доставки сообщения остаются в очереди. Критическая ошибка: Telegram со звуком и попыткой закрепления, консоль и сигнал Windows; напоминания через 1 минуту, затем через 5 минут, далее каждые 15 минут. Работает отдельный поток, которому не мешает пересчёт лотов.
/sr_ack НОМЕР — отключить напоминания по проверенному заказу; /sr_ack all — все текущие напоминания. Команда не меняет статус заказа, не снимает паузу и не закупает товар.
/sr_notify_test — проверить Telegram без покупки. Включи уведомления и звук этого бота на телефоне. Для выполнения заказов компьютер, интернет и окно бота должны работать.
Заказы K87NUSE1 и C4T5QW2U помечены в личной базе как выполненные владельцем; они не будут закуплены повторно. Автоматическая выдача исправления проверена тестами и чтением FunPay, реальные покупки для проверки не совершались.


ОБНОВЛЕНИЕ 0.12.0: ОФОРМЛЕНИЕ, ПОМОЩЬ, ВАЛЮТЫ, ОТЧЁТЫ
Компьютер и окно бота должны оставаться включены. Запускай Start_STEAMRU_LIVE.bat, введи данные локально. /sr_resume один раз включает обработку и доступные по балансу товары. Если не хватает денег ни на один товар, бот продолжает работу с выключенными лотами и проверяет баланс; после пополнения доступные лоты восстанавливаются автоматически. Внешнее пополнение кошелька бот не оплачивает.

Новые лоты Steam: USD 1–5, KZT 600–2500, только целые единицы. RUB остаётся 100–500 ₽. Цена лота в рублях за 1 единицу выбранной валюты. Доступное количество ограничивается живым USD-балансом, резервом, очередью и лимитом одной покупки. Steam USD не означает USD (Турция).
Blizzard: карты США $5/$10 и Европы €20. Они имеют разные товары и регион; автоматически выдаётся код. Перед покупкой проверь регион/валюту Battle.net. По текущему лимиту $6 карты $10 и €20 не будут включаться. /sr_limits меняет бюджеты по твоей явной команде; данное обновление лимит $6 не поднимает. При следующем запуске API повторно проверит все новые товары, цены и поля.

Команды покупателя в FunPay:
!помощь — срочно вызвать продавца; !help — тот же вызов.
!статус — статус своих заказов в этом чате; !status — то же.
О вызове помощи придёт тревога в личный Telegram владельца, закрепление, сигнал Windows и напоминания. Один покупатель не создаст больше одного нового вызова в 5 минут. Помощь не останавливает продажи. Чтобы после ответа отключить напоминания: /sr_ack НОМЕР. Если обращение без заказа, в тревоге указан HELP_ID; /sr_ack HELP_ID. /sr_ack all — все текущие тревоги.

Бот проверяет баланс и наличие раз в минуту, каталог и цены — раз в час. Автоматически восстанавливает доступные предложения, сохраняет ручное отключение, временные цены, закрепление игр и уже оплаченные заказы. Ключи ротируются до 3 игр каждые 5 часов с защитой открытых заказов.
Раз в час Telegram получает подробный отчёт: баланс, какие цены изменились (до/после), какие лоты открылись или закрылись, какие игры начали заменяться и чем закончилась замена, какие товары появились и какие заказы выполнены. Журнал сохраняется при перезапуске. /sr_report — отправить отчёт сейчас. О действиях во время работы приходят отдельные уведомления; срочные события и заказы идут перед обычным журналом. Отправка идёт с паузами, при ограничении Telegram сообщения сохраняются и ждут разрешённого повтора. Включи звук и уведомления этого бота на телефоне.

Названия с эмодзи обновляются там, где категория FunPay поддерживает свободный заголовок. Если название генерируется из валюты/номинала, правильные поля не подменяются: оформление улучшается в описании и сообщениях. Исходные названия оплаченных товаров продолжают распознаваться.
Покупатель получает понятное сообщение об очереди и выполнении, результат выдачи, активацию кода, ссылку на подтверждение и просьбу оставить отзыв. Шаблоны: НОВЫЕ_ШАБЛОНЫ.txt. Примеры в этом файле не являются реальными заказами.
Проверки проведены без покупок. После потерянного ответа POST вторая закупка не создаётся; известно созданный заказ проверяется через GET. Возвратом считается только refunded.
